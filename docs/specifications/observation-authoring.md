# Observation Authoring v0.2

## 1. Purpose

Sensory rules decide **who** perceives an event. Something still has to decide **what** each
perceiver's Observation contains, and whether that is text, structure, or both. Done naively
("ask the model to describe what each observer saw") this multiplies calls by the number of
observers. This document fixes the design: Observations are structured and rendered, not
written.

> **Observations are generated by template from events. They are rendered into prose only
> when a model or the human needs to read them, and never stored as model-written text.**

## 2. Observation content

```yaml
observation:
  actor_id, source_event_id, channel, confidence, game_tick
  raw:                      # structured, template-generated, deterministic
    event_type: ...
    participants: [{entity_id, known_as: <name per actor's identity knowledge | "a stranger" | "a hooded figure">, role}]
    outcome_visible: {...}  # only the fields the sensory rule exposes (e.g. "struck", not "7 damage")
    details: [...]          # from event payload fields marked `visible_to: observers`
  interpreted_text: null    # optional; see §4
```

### Template rules

- Each event type declares which payload fields are **observer-visible**, **participant-only**
  (own HP change, own roll), or **hidden** (seed, hidden modifiers, deception flags).
- Names are substituted per observer via `entity_identity_knowledge`; unknown entities are
  described by a deterministic descriptor from the entity's `metadata.descriptor`
  ("a tall woman in a grey cloak") set at creation/materialization.
- Degraded channels (dark, distant, obstructed) drop fields per the sensory rule and lower
  `confidence`; a `partial` observation lists what was perceived, not what was missed.
- Speech events attach the verbatim text only for recipients with comprehension; others get
  `speech_in_unknown_language` (see `communication-and-knowledge.md` §4).

No model call is involved in producing `raw`.

## 3. Rendering for models

The Context Compiler renders an actor's recent `raw` observations into compact prose-like
lines when assembling context ("Renn struck the thief; the thief fell." / "Mira glanced at the
door before answering."). Rendering is a deterministic function of `raw` plus the actor's
identity knowledge, so the same observation renders identically for the same actor every
time, and it costs no inference. Rendered lines are not stored.

## 4. `interpreted_text` (optional, model-written)

A model may attach interpretation **only** through the Memory Processor, when it decides what
an actor retains, and only into the resulting Memory's `subjective_summary` — not back into
the Observation. The one exception: an explicit insight/awareness mechanic that returns a
structured "tell" (`reveal_information` effect) may write a short deterministic
`interpreted_text` from the rule's own template ("he hesitated before answering").

Rationale: keeping Observations model-free keeps replay deterministic and leakage
analysis mechanical.

## 5. Human narration

The Narrator receives the focus actor's rendered observations (§3) plus the verbatim dialogue
that actor heard and writes the human-facing prose once per turn. That prose is presentation
(`api-contracts.md` §9) and is never fed back as anyone's Observation, including the human
actor's — the human actor's Observations come from the same templates as everyone else's.

## 6. Memory Processor input

Receives: the actor's `raw` observations for the checkpoint window (rendered), verbatim
dialogue heard, current goals/emotions/relationships, and relevant prior memories. It does
**not** receive the human-facing narration, which may contain flavor the actor did not
perceive and style the actor does not have.

## 7. Tests

- Same event, three observers with different identity knowledge → three Observations whose
  `participants[].known_as` differ as expected, with zero model calls.
- Degraded channel drops the specified fields and lowers confidence.
- Rendering is pure: rendering the same observation twice yields identical text.
- Narrator prose is absent from every actor's Observation and Memory source lineage.
